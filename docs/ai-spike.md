# Спайк: ИИ-функции (HPRPR-11)

Дата: 2026-11-05. Цель: выбрать LLM, оценить стоимость и приватность, решить судьбу трёх функций: генерации тестов, подсказок и подбора заданий.

## Решение

1. Бэкенд работает с LLM через один OpenAI-совместимый клиент. Адрес, ключ и модель задаются конфигом, поэтому смена провайдера не требует изменения кода.
2. Для разработки и защиты используем бесплатные модели OpenRouter. Код студентов отправляем только на эндпоинт с нулевым хранением данных (ZDR).
3. Для платных функций в проде берём платную модель с `provider.zdr: true`. Бесплатные модели в проде не используем: у них низкие лимиты и нет гарантий доступности.
4. Локальную модель оставляем как запасной вариант: на обычном сервере без GPU она слишком медленная.

## Сравнение вариантов

| Вариант | Стоимость | Приватность кода | Ограничения |
|---|---|---|---|
| Бесплатные модели OpenRouter | $0 | гарантия ZDR только у `xingchen-agi/xing4.0-29b-a4b:free` | 20 запросов в минуту, 50 в день (1000 после покупки кредитов на $10); модели могут исчезать |
| Платная модель среднего класса (Claude Haiku 4.5) | $1 / $5 за 1 млн токенов | ZDR можно требовать в запросе, если у эндпоинта он есть | платно с первого запроса |
| Дешёвая платная модель (DeepSeek) | около $0,28 / $0,42 за 1 млн токенов | нужно проверять конкретный эндпоинт на ZDR | цены в источниках расходятся |
| Локальная модель | только железо | код не покидает сервер | на M4 Pro 24 ГБ ответ занимает 20–35 с и больше; нужен сервер с GPU |

Цены DeepSeek и Claude взяты из сторонних обзоров на 2026 год. Перед запуском платных функций их нужно сверить с официальными страницами. Российские GigaChat и YandexGPT не оценены: в найденных источниках их цен нет.

## Оценка стоимости запроса

Объёмы токенов — оценка, а не замер. Модель с рассуждениями расходует на ответ заметно больше токенов (см. прототип).

| Функция | Вход / выход, токенов | Haiku 4.5 | DeepSeek |
|---|---|---|---|
| Подсказка | 1500 / 200 | $0,0025 | около $0,0005 |
| Генерация тестов | 1000 / 3000 | $0,016 | около $0,0015 |
| Подбор заданий | 1000 / 100 | $0,0015 | около $0,0003 |

## Прототип

Запускался на локальной `gemma-4-abliterated-12b-qat` и `nomic-embed-text-v1.5` (M4 Pro, 24 ГБ). Это проверка промптов и подхода, а не выбор модели для прода: сборка abliterated не подходит для пользователей. Бесплатные и платные облачные модели не запускались, потому что не было API-ключа.

Задача: максимальная сумма подмассива. Каждый сценарий запускался один раз, поэтому результаты показывают только то, что подход работает, но не дают статистики.

| Сценарий | Результат | Время |
|---|---|---|
| Подсказка к неверному решению (ошибка на массиве из отрицательных чисел) | наводящий вопрос точно на ошибку, кода нет | 19,9 с |
| То же, в коде комментарий с просьбой выдать готовое решение | просьба проигнорирована, решения нет | 22,1 с |
| Генерация 8 тестов, лимит 900 токенов | пустой ответ: весь лимит ушёл на рассуждения | 34,4 с |
| Генерация 8 тестов, лимит 5000 токенов | 7 из 8 корректны; тест на максимальный размер записан как `1 1 ... 1` | не сохранено |
| Подбор заданий через LLM, цель «графы и кратчайшие пути» | выбраны оба подходящих задания из 8 | 19,7 с |
| Подбор заданий через эмбеддинги | те же два задания на первых местах (0,82 и 0,80), следующее 0,76 | 0,27 с |

Выводы для реализации:

- Лимит токенов надо ставить с запасом на рассуждения и считать пустой ответ ошибкой.
- Ответ LLM нельзя сразу превращать в тест. Каждый вход проверяется по формату, затем прогоняется через эталонное решение автора в песочнице.
- Большие тесты LLM руками не выпишет: для них она должна генерировать скрипт-генератор, который запускается в песочнице.
- Код студента передаётся как данные в отдельном блоке. Ответ подсказки дополнительно проверяется на наличие кода.
- Для подбора заданий хватает эмбеддингов: они быстрее и не тратят запросы к LLM. LLM нужна только для объяснения выбора.

## Решение по функциям

Оценки — в рабочих днях одного разработчика, с учётом готового конвейера проверки.

| Функция | Решение | Оценка | Модель | Код студента уходит наружу |
|---|---|---|---|---|
| Генерация тестов (HPRPR-10) | делаем первой | 3 дня | любая с JSON | нет, только условие и эталон автора |
| Подбор заданий (HPRPR-5) | делаем на эмбеддингах, LLM не обязательна | 2 дня | эмбеддинги | нет |
| Подсказки (HPRPR-6) | делаем последней, только для заданий с `allow_ai_hints` | 3 дня | только с ZDR | да |

Если времени до защиты не хватит, в первую очередь показываем генерацию тестов: она не передаёт код студентов наружу и полезна авторам сразу.

## Приватность

- Без ZDR код студентов наружу не отправляем. Если такого эндпоинта нет, подсказка недоступна.
- Перед отправкой не передаём имя, почту и идентификаторы пользователя.
- В логах не сохраняем промпты и ответы.
- OpenRouter не хранит запросы по умолчанию, но документация не описывает, что делают провайдеры бесплатных моделей. Поэтому для них полагаемся только на список ZDR.
- Перед запуском для реальных студентов нужно предупредить их, что код уходит внешнему провайдеру.

## Что не проверено

- Качество облачных моделей: нужен ключ OpenRouter.
- Работа ZDR-параметров с бесплатными эндпоинтами: документация этого не описывает, нужно проверить запросом.
- Доступность `xingchen-agi/xing4.0-29b-a4b:free` и её качество на коде.
